College Project Hub

A Unified Academic Project Management, Multi-Criteria Evaluation & Showcase Ecosystem

Key Innovations:

• Hierarchical Academic Data Structure (Year → Section → Team → Project)
• One-Time Verification & Single-Submission Lock Protocol
• 4-Tier Rubric Scoring (Technical Approach, Idea, Design Thinking, UI/UX)
• Automated Instant Scorecard Dispatch via Nodemailer

Technology Stack:
MERN Stack (MongoDB, Express, React, Node.js) + Tailwind CSS + JWT
The Motivation

Problem Statement & Institutional Challenges

Current project management processes in higher education suffer from fragmentation and lack of governance.

📂
Disorganized Submissions
Spreadsheets, emails, and drive folders create duplicate versions, broken GitHub links, and missing documentation.
⚖️
Subjective & Unstandardized Grading
Absence of standardized scoring rubrics leads to opaque faculty grading with zero automated feedback loops to student leads.
🔒
Orphaned Projects & Zero Showcase
Once graded, projects remain hidden on local drives. Juniors cannot explore past innovations, and recruiters cannot verify project authenticity.
The Solution

The Proposed Solution & System Objectives

A standardized web-based platform bridging students, faculty, and public discovery.

🏛️
Rigorous Academic Hierarchy
Faculty configure Academic Years, Sections, and Team Rosters. Each team lead receives auto-generated credentials to preserve isolation and accountability.
🔒
Tamper-Proof Submission Lock
Team leads verify credentials and submit repository links and abstracts. The interface immediately locks to prevent post-deadline tampering.
📊
Multi-Pillar Rubric Scoring
Faculty evaluate across Technical Approach, Idea, Design Thinking, and UI/UX with granular sliders, leaving feedback that automatically dispatches to students.
🌟
Public Institutional Showcase
An interactive showcase with dynamic Year and Section filters, allowing juniors, faculty, and recruiters to inspect vetted projects and evaluation badges.
System Design

Full-Stack System Architecture

Decoupled client-server MERN stack architecture with secure RESTful APIs.

1. Presentation Tier (Frontend)
  • ▸React 18 + Vite for high-performance SPA
  • ▸Tailwind CSS for responsive UI design
  • ▸Context API for Teacher & Team Lead session state
  • ▸Axios Interceptor for automatic JWT authorization
2. Application Tier (Backend)
  • ▸Express.js RESTful API endpoints
  • ▸Authentication: bcrypt password hashing + JWT tokens
  • ▸Cascade Delete utilities to maintain data integrity
  • ▸Nodemailer transactional email micro-service
3. Data & Communication Tier
  • ▸MongoDB document database
  • ▸Mongoose ODM schemas with relational references
  • ▸SMTP Email Server (Gmail App Password / Local fallback)
  • ▸Cross-Origin Resource Sharing (CORS) secured
Database Design

Relational Hierarchy & Mongoose Models

Structured data modeling ensuring strict referential integrity and safe cascading operations.

Entity Relationships
Year (e.g., 2024-2025)
└── Section (e.g., CSE-A)
    └── Team (Roster, Lead Email, Auto-Credential)
        └── Project (Title, Repo, Rubric Scores, Status)
Isolated Teacher schema handles faculty credentials with bcrypt hashing and JWT generation.
Cascade Delete Utility (cascadeDelete.js)
  • ✔Year Removal: Deletes dependent sections, teams, and associated project artifacts.
  • ✔Section Removal: Purges all teams and submissions belonging strictly to that branch.
  • ✔Team Removal: Cleans up orphaned project records and invalidates credentials.
  • ✔No Dirty Reads: Eliminates broken references on the public showcase cards.

Operational Flow

End-to-End Operational Lifecycle

A seamless 5-stage automated journey from institutional setup to public showcase.

Step 01
Hierarchy Setup
Faculty logs in and creates the Academic Year, Branch/Section, and registers Team names with Lead Email.
Step 02
Credential Generation
System auto-generates a secure password and emails the team lead with login instructions.
Step 03
Project Submission
Team lead verifies credentials at /upload, inputs GitHub URL and abstract. Form permanently locks.
Step 04
Rubric Evaluation
Faculty accesses "Unrated Projects", scores the 4 criteria sliders, adds remarks, and submits.
Step 05
Scorecard & Showcase
Scorecard emails immediately to the student. Project moves to public showcase with a verified badge.
Core Feature 1

Faculty Portal & Academic Management

Comprehensive 6-tab dashboard giving educators centralized control.

Dashboard Tab Architecture
  • 1.Academic Hierarchy: Add/manage Years & Sections with validation.
  • 2.Team Rosters: Register leads, manage member lists, generate credentials.
  • 3.Submission Tracker: Real-time overview of pending vs submitted teams.
  • 4.Unrated Projects Queue: Direct access to newly submitted work.
  • 5.Rated Projects Archive: Searchable repository of evaluated projects.
  • 6.Faculty Account Settings: Secure password changes and profile data.
Smart Credential Provisioning

When a faculty adds a team, the backend creates an isolated credential set:

Team: Team Alpha
Section: CSE-A | Year: 2024-2025
Lead Email: lead@college.edu
Auto Password: [Generated 8-char Secure Token]

Dispatched via emailTemplates.js or printed to the terminal console during local testing.

Core Feature 2

Team Lead Verification & Submission Lock

Preventing duplicate entries, late tampering, and unauthorized modifications.

Phase 1: Verification Gate
  • ▸Student navigates to /upload.
  • ▸Enters registered Lead Email and auto-generated password.
  • ▸Backend verifies team existence, academic year, and checks if project is already submitted.
  • ▸Unlocks project submission form only upon successful match.
Phase 2: Immutable Submission Lock
  • 🔒Immediate Lockout: Once the submit button is triggered, the project is saved with state status: 'submitted'.
  • 🔒Duplicate Prevention: Subsequent login attempts alert the student: "Project already submitted and locked for evaluation."
  • 🔒Academic Integrity: Protects against race conditions and post-review code swaps.
Core Feature 3

Standardized Multi-Criteria Rubric Scoring

Transparent, balanced evaluation with quantitative metrics and qualitative feedback.

1. Technical Approach
Code quality, architectural robustness, backend security, algorithmic efficiency, and database schema design.
2. Idea & Innovation
Novelty of solution, domain relevance, problem-solving capability, and practical real-world utility.
3. Design Thinking
Modularity, edge-case handling, system maintainability, cascading integrity, and extensibility.
4. UI & UX Polish
User interface responsiveness, accessibility, intuitive workflow navigation, and visual feedback.
Faculty Feedback Modal (RatingModal.jsx):

Includes a dedicated remarks textarea for constructive critique. When saved, the project automatically transitions from the "Unrated" queue to "Rated Projects", triggers a badge, and fires the email dispatcher.

Core Feature 4

Automated Notification & Scorecard Dispatch

Closing the evaluation feedback loop with responsive HTML emails.

Responsive HTML Templates (emailTemplates.js)
  • ✉Clean, mobile-responsive HTML layout with institution branding.
  • ✉Itemized breakdown of all 4 rubric scores out of 10/25.
  • ✉Aggregated final grade percentage and faculty remarks.
  • ✉Direct link to the project's public scorecard page.
Dual-Mode Dispatch Architecture
  • ⚡Production Mode: Uses real SMTP credentials (e.g. Gmail App Password, AWS SES) for live mailbox delivery.
  • ⚡Development Mode: Features a simulated fallback logger that displays formatted emails in terminal logs without requiring active SMTP keys.
  • ⚡Zero blocker during offline viva or laboratory demonstrations.

Security & Quality

Security, Performance & Architectural Resilience

Adopting enterprise-grade patterns for privacy, reliability, and data consistency.

Authentication & Access Control
  • 🔐Bcrypt Password Hashing: Salted password encryption prevents credential theft in database breaches.
  • 🔐Stateless JWT: Bearer tokens verify faculty identity across protected REST endpoints.
  • 🔐Axios Interceptors: Automatically attaches JWT authorization headers to all authenticated outgoing requests.
Data Integrity & Reliability
  • 🛡️Cascading Deletion Guards: Removes orphan records when years or sections are deleted.
  • 🛡️Single Submission Lockdown: Eliminates duplicate submissions or race conditions.
  • 🛡️Defensive Error Handlers: Graceful API responses with meaningful HTTP status codes.
